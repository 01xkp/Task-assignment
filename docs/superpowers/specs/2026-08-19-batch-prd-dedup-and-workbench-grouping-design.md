# 批量 PRD 去重与工作台分组设计

## 目标

支持一次导入多份本地 PRD，并确保相同需求正文不会重复进入文档库或生成重复任务。工作台的“分析新需求”能够从已有 PRD 中多选，按顺序独立分析。PRD 文档和工作台分组均按最近导入或更新优先；工作台列表以 PRD 为父级，展开后展示任务类别与任务。

## 范围与约束

- 本次批量导入面向本地文件，支持现有的 PDF、DOCX、MD、TXT 和 JSON 格式，单文件上限继续为 10 MB。
- URL 和粘贴正文仍为单项输入，但也必须复用同一去重规则。
- 批量分析按所选 PRD 的顺序串行执行，每份 PRD 使用独立模型调用、独立结果和独立 `prdId`。
- 不改变模型配置、模型选择或现有模型超时策略。
- 内容相同的 PRD 被视为同一需求。不同正文即使文件名相同，也允许作为新的 PRD 导入。
- 本设计不使用模型判断两份不同文字是否“语义相同”。这种判断不可重复验证且可能错误合并真实的版本更新；文档级去重以可审计的正文指纹为准。

## 方案选择

### 文件名去重

实现简单，但会漏掉不同文件名的副本，也会错误阻止同名更新，不能满足需求。

### 规范化正文指纹去重（采用）

读取文件后按确定步骤规范化：转换为 Unicode NFC、将 CRLF/CR 统一为 LF、将不换行空格统一为空格、压缩行内连续空白、最多保留一个空白行，并去除首尾空白；随后计算 SHA-256 指纹。相同内容始终得到相同指纹；同名且内容变更会得到新指纹。它不依赖模型、速度快，并可通过单元测试稳定验证。

### 模型语义去重

可发现措辞不同但业务相似的文档，但成本高、结果不稳定，并可能把真实的新版本或相近需求误判为重复。本次不采用。

## 数据与服务端设计

### PRD 指纹与排序字段

每条 PRD 新增并持久化以下字段：

- `contentFingerprint`：规范化正文的 SHA-256 值。
- `updatedAt`：导入成功时写入；一次分析成功保存任务后也写入。

新增纯函数模块 `server/prds.js`，负责：

- 规范化正文和生成指纹；
- 为一个或多个已解析 PRD 创建存储记录；
- 在单次状态更新中同时检查现有指纹和当前批次已见指纹；
- 返回 `imported`、`duplicates` 与 `failed` 三组结果；
- 按 `updatedAt`（缺失时回退 `createdAt`）倒序排序 PRD。

所有 PRD 输入来源都经过这个模块。这样批量文件、单文件、URL 和手动粘贴不会因入口不同而绕过去重。去重检查放在 `updateState` 的同一写入事务中，避免并发请求同时插入相同正文。

### 批量上传 API

`POST /api/prds/upload` 接受 `files` 多文件字段，同时兼容旧的 `file` 字段。服务端逐个解析文件：

- 解析失败只进入 `failed`，不影响其他文件；
- 正文重复项不写入，进入 `duplicates`，并带上已存在 PRD 的标题和 ID；
- 其余项写入 `imported`。

响应包含三组结果，因此前端可以精确显示导入数、跳过的重复项和失败原因。URL 或粘贴正文遇到重复时返回清晰的重复提示，而不创建第二条 PRD。

### 批量分析 API

新增批量 SSE 分析入口，接收唯一的 `prdIds` 数组。服务端按传入顺序依次调用既有单 PRD 分析流程，并发送批次开始、单项进度、单项成功/失败和批次完成事件。

- 请求中重复的 PRD ID 会在服务端去重，防止同一批次重复分析。
- 某一份 PRD 模型失败、超时或被占用时，记录该项失败并继续后续 PRD。
- 现有 `activePrdAnalyses` 继续阻止相同 PRD 的并发分析。
- 单 PRD 分析接口保留，供“重新分析”操作和兼容现有调用。

### 任务重复保护

模型结果进入状态前生成任务指纹，组成部分为标准化的标题、模块、模块路径、工作类别和排序后的平台。每次分析会：

1. 合并模型响应内指纹相同的任务，只保留第一项；
2. 移除当前 PRD 的未完成旧任务；
3. 保留已完成或已取消任务，但过滤与其指纹相同的新任务；
4. 仅写入剩余的新任务，并将 PRD 的任务数更新为该 PRD 所有关联任务（包括保留历史）的总数。

这保证同一 PRD 的重新分析不会把相同需求再次写入任务列表，同时保留已完成或取消任务的历史。

## 前端交互设计

### 批量导入

`ImportPrdModal` 的本地文件模式改为多选和多文件拖放，并在提交前显示文件清单。导入结果页分别列出：成功导入、因正文重复跳过、读取失败。重复项不可继续分析。

### 分析新需求

从任务工作台点击“分析新需求”时，弹窗默认进入“已上传 PRD”选择页。用户可多选处于可分析状态的 PRD，然后提交一次批量分析。进度界面显示总进度、当前 PRD、队列位置及每项结果；单项失败后继续，最终汇总成功和失败数量。

普通“导入 PRD”入口仍以本地文件输入为默认页。导入成功后用户可在结果页选择刚导入且未重复的 PRD 直接批量分析。

### PRD 排序

`publicState` 对 PRD 使用统一的最近优先排序，供 PRD 文档页、工作台当前需求提示和任务分组共同使用。导入和成功分析都会更新时间，因此最新导入或更新的 PRD 始终位于顶部。

### 工作台分组

任务工作台的列表视图改为三层：

1. PRD 父级行，显示标题、更新时间、分析状态和任务总数；
2. 展开的工作类别：`共享实现`、`平台适配`、`平台验收`；
3. 展开的类别中的具体任务行，沿用现有负责人、工时、截止日期、状态和查看任务操作。

最新 PRD 默认展开，父级与类别的展开状态在当前页面会话内保持。没有任务的已上传 PRD 也显示父级行和待分析状态。搜索、负责人和状态筛选仅显示匹配任务及其必要父级；负载视图继续按成员显示，不改变现有排期用途。

## 代码边界

- `server/documents.js`：继续负责文件解析与中文文件名处理；不承担存储策略。
- `server/prds.js`：正文规范化、指纹、批次入库结果和 PRD 排序。
- `server/index.js`：上传字段适配、批量 SSE 编排、调用 PRD 与任务保护帮助函数。
- `server/model.js`：保留任务类别枚举；分析结果落库前调用任务去重帮助函数。
- `src/api.js`：新增批量上传和批量分析流读取方法，并保持单项方法兼容。
- `src/App.vue`：管理批量分析状态、通知与视图入口。
- `src/components/ImportPrdModal.vue`：文件清单、重复反馈、已上传 PRD 多选和批次进度。
- `src/components/PrdView.vue`：展示统一的最近优先排序结果。
- `src/components/WorkbenchView.vue` 与 `src/styles.css`：实现 PRD/工作类别折叠分组列表，同时保留负载视图。

## 错误处理

- 同一批次内重复正文：仅导入第一份，其他项标为重复并显示其对应保留项。
- 已存在正文重复：不新增 PRD，显示已有 PRD。
- 单个文件解析失败：显示失败原因，其他文件继续处理。
- 批量分析单项失败：保留失败原因、继续队列，其余成功项仍保存任务。
- 同一 PRD 正在分析：该批次项标为占用，后续 PRD 继续。
- 分析保存前 PRD 被删除：该项失败，不写入孤立任务。

## 验证策略

Node 测试新增覆盖：

- 换行、空白或 Unicode 形式差异的相同正文产生相同指纹；
- 不同内容产生不同指纹；
- 同一批次和已有文档库的重复正文只保留一条；
- 相同文件名、不同正文可以导入；
- PRD 最近更新优先排序与稳定的同时间回退顺序；
- 模型结果中的重复任务、以及重新分析与已完成任务重复时都不会再次写入；
- 批量请求中的重复 PRD ID 只分析一次，某项失败不阻断后续项。

实现完成后运行 `npm test` 和 `npm run build`；在本地启动服务后手工验证批量导入、重复反馈、批量分析进度、重新分析和两种工作台视图。
